
## Claude Codeは、回答だけでなく開発作業を支援するツール

Claude Code（クロードコード）は、コードを読み、ファイルを編集し、コマンドを実行するAIツールです。2026年10月10日に確認した[公式概要](https://code.claude.com/docs/en/overview)は、機能の開発、不具合修正、開発作業の支援を用途として紹介しています。

「質問への回答を読む」だけでなく「手元のファイルが変更される」可能性があります。したがって、使い方を覚える前に、渡すフォルダ、変更を許可する範囲、元に戻す方法を決めます。文章の下書きだけが目的なら、Codeから始める必要はありません。AIアシスタントとしての概要は[Claudeとは何ですか。無料でできること、料金、ChatGPTやClaude Codeとの違いは？](/posts/claude-towa)で扱っています。

本記事の製品情報の確認日は2026年10月10日（日本時間）です。以下の試し方、架空の依頼文、テスト項目は当事務所の提案であり、実在する支援先の実績や削減時間を示すものではありません。

## 初心者はデスクトップ、ターミナルに慣れている人はCLI

2026年10月10日確認の[デスクトップ導入案内](https://code.claude.com/docs/en/desktop-quickstart)では、公式アプリのCodeタブから、ターミナルを使わずに手元のプロジェクトを扱えます。同日の[CLIクイックスタート](https://code.claude.com/docs/en/quickstart)は、ターミナルでのインストール、ログイン、作業開始を案内しています。

| 比較する点 | デスクトップのCodeタブ | ターミナルのCLI |
| --- | --- | --- |
| 開始方法 | 公式アプリでCodeを開き、Localとフォルダを選ぶ | CLIを導入し、プロジェクトのフォルダで起動する |
| 依頼方法 | 画面の入力欄に自然な言葉で書く | 起動したセッション内に依頼を書く |
| 変更の点検 | 差分ビューで変更を確認する | 変更内容をエディタなどで確認する |
| 初回の確認 | 利用できる契約、選択フォルダ、権限モード | OSに合う導入方法、認証経路、権限モード |
| 本記事での選び方 | ターミナル操作に慣れていない人の入口 | コマンドと開発環境を理解できる人の入口 |

製品の操作説明は上記2つの公式ページ、確認日は2026年10月10日です。選び方は当事務所の提案です。画面が使いやすいことと、変更の安全性を確認できることは別なので、コードを確認できる担当者も決めてください。

## 始める前に用意する4つの条件

1. 会社が認めるアカウント・契約と、入力できる情報の範囲。
2. 個人情報、取引先資料、秘密情報、認証情報を含まない練習用フォルダ。
3. 作業前のコピーまたはバージョン管理と、元の状態へ戻す手順。
4. 変更内容とテスト結果を確認する担当者。

本番の共有フォルダ、実際の顧客データ、稼働中のシステムを最初の対象にしないでください。練習用コピーでも、元のフォルダに含まれるAPIキーや設定ファイルをそのまま持ち込まないよう点検します。

2026年10月10日確認の[公式セキュリティ資料](https://code.claude.com/docs/en/security)では、Manualで作業フォルダ外のファイル操作に承認を求める一方、承認されたBashコマンドは利用者のOS権限で別の場所に書き込めると説明しています。フォルダを選ぶだけでは隔離になりません。権限を狭くした検証環境なども、担当者と相談してください。

## デスクトップでの使い方：6つの手順

操作の根拠は2026年10月10日に確認した[公式デスクトップ導入案内](https://code.claude.com/docs/en/desktop-quickstart)です。安全な試し方の補足は当事務所の提案です。

### 1. 公式アプリを導入し、契約を確認する

[公式導入案内](https://code.claude.com/docs/en/desktop-quickstart)からOSに合う方法を選び、インストールしてログインします。Codeタブを開く際に契約の案内が出る場合は、会社が利用を認めるプランと費用を確認してから進めます。公式案内では、デスクトップのCodeタブを使うためにNode.jsやCLIを別に導入する必要はないと説明しています（2026年10月10日確認）。

### 2. CodeタブでLocalと練習用フォルダを選ぶ

Codeタブを開き、環境をLocalにして、Select folderから練習用フォルダを選びます。Localは手元のファイルを直接扱う選択肢です。Cloudなどは別の実行環境なので、最初から混ぜず、本記事はLocalの手順に限定します。

Localを選んでも、AIサービスへの情報送信がなくなるわけではありません。扱うデータと契約条件の確認は必要です。

### 3. 作業を頼む前に権限モードを確認する

送信ボタン付近のモード表示を確認します。「初期状態だから必ず毎回承認される」とは考えないでください。[公式権限モード資料](https://code.claude.com/docs/en/permission-modes)は、環境、バージョン、設定によって開始時のモードが異なると説明しています（2026年10月10日確認）。

| モード | 公式案内の動作の概要 | 最初の練習での注意 |
| --- | --- | --- |
| Manual | ファイル編集やコマンド実行の前に承認を求める | 既存の許可設定も確認し、内容を理解してから承認する |
| Plan | ソースを変更せず、調査して計画を提案する | 計画作成中に調査用コマンドが動く場合がある |
| Accept edits | ファイル編集を自動承認する | ファイルが変わってから差分を読む運用になる |
| Auto | 別の判定モデルが行動を評価する | 人による変更確認や安全性の保証の代わりではない |

出典は2026年10月10日確認の[公式デスクトップ導入案内](https://code.claude.com/docs/en/desktop-quickstart)と[公式権限モード資料](https://code.claude.com/docs/en/permission-modes)です。最初は計画を確認するためPlanを選び、実装へ進むときにManualへ切り替えて、画面の表示と設定を再確認する方法があります。計画承認画面で別モードに移る選択肢を選んでいないかも確認します。

Planを「OSレベルで読み取り専用になる機能」とは扱わないでください。公式資料には環境による例外もあり、モード設定だけで安全が保証されるわけではありません。承認の省略を目的に権限を広げることは、最初の練習では避けます。

### 4. 最初は説明と計画だけを頼む

以下は機密情報のない練習用プロジェクトに対する依頼例です。実際の動作を保証する指示文ではなく、権限設定と合わせて使います。

```text
この練習用フォルダの構成と、各ファイルの役割を説明してください。
今回はソースの変更、削除、外部サービス接続をしないでください。
「月別の売上合計を表示する練習用ツール」に、空欄の入力への注意表示を
追加したいです。変更候補のファイル、方法、必要なテストを先に示してください。
不明点は推測せず、確認が必要と書いてください。
```

説明されたファイルが本当に存在するか、既存の処理をどう理解しているかを確かめます。依頼文で「変更しない」と書くだけでなく、実行環境とモードも確認するのが要点です。

### 5. 小さな変更を1つだけ頼み、差分を読む

計画を理解できたら、Manualで「空欄への注意表示だけを追加する」など範囲を絞ります。変更候補と差分を読み、承認します。差分とは、どのファイルのどの行が追加・削除・変更されるかを示すものです。

2026年10月10日確認の[公式デスクトップ導入案内](https://code.claude.com/docs/en/desktop-quickstart)では、Manualで変更ごとにAccept・Rejectを選べ、適用後にも差分ビューを開いて確認できると説明しています。分からないコードやコマンドはそのまま承認せず、目的と影響範囲の説明を求めます。

### 6. 動作を検証し、業務への反映を別に判断する

テストの実行が必要なら、そのコマンドと対象を担当者が確認してから承認します。AIの「完了しました」という文章だけで判定せず、実際の入力と出力を見ます。以下は架空の練習用ツールのテスト例です。

| 入力例 | 確認する内容 |
| --- | --- |
| 100、200、300 | 合計が600になるか |
| 空欄 | 計画した注意表示になるか |
| 数字でない文字 | 意図せず処理が進まないか |
| 同じ操作をもう一度 | 二重に処理されないか |

この4例だけで安全性や品質を証明できるわけではありません。保存、権限、通信、実際の業務の例外なども必要に応じて追加します。変更前の機能が壊れていないかも確認し、本番に反映する担当、戻す手順、保守の担当を決めてから使います。

## CLIを使う場合は、OSに合った公式手順から

ターミナルに慣れている人は、2026年10月10日に確認した[公式CLIクイックスタート](https://code.claude.com/docs/en/quickstart)を参照してください。インストール方法はOSやシェルによって異なるため、別のOS用のコマンドをそのまま貼り付けないでください。取得したスクリプトを実行する方式では、取得元と実行内容を理解できる担当者が確認します。

導入後のバージョン確認は次のコマンドです。これはインストール自体のコマンドではありません（2026年10月10日確認、[公式CLI案内](https://code.claude.com/docs/en/quickstart)）。

```text
claude --version
```

練習用プロジェクトのフォルダに移動し、計画モードで起動する例は次のとおりです（2026年10月10日確認、[公式権限モード資料](https://code.claude.com/docs/en/permission-modes)）。本記事の説明を読んだだけでコマンドを実行せず、利用環境の設定も確認してください。

```text
claude --permission-mode plan
```

初回の認証経路と請求先を確認します。サブスクリプションで利用する場合とConsole・API経由で利用する場合を混同しないでください。デスクトップとCLIを同じ作業に同時投入する必要はありません。

## 無料で使えるか。Pro・MaxとAPIの費用を分ける

2026年10月10日確認の[公式料金ページ](https://claude.com/pricing)の個人向け比較では、FreeにClaude Codeは含まれず、ProとMaxには含まれます。

| 個人向けプラン | 掲載価格 | Claude Code | 注意点 |
| --- | --- | --- | --- |
| Free | 0米ドル | 含まれない | Claudeの無料利用とCodeの利用を混同しない |
| Pro | 月払いで月額20米ドル | 含まれる | 年払いは別条件。利用上限がある |
| Max | 月額100米ドルから | 含まれる | 選択する利用枠で条件が異なり、上限がある |

価格と機能の出典は2026年10月10日に確認した[公式料金ページ](https://claude.com/pricing)です。適用される税金は含まれません。円換算した固定価格や、毎月の請求総額を示す表ではありません。契約時の表示を確認してください。

同日の[公式CLIクイックスタート](https://code.claude.com/docs/en/quickstart)には、Claude Consoleアカウントの前払いクレジットによるAPIアクセスも記載されています。サブスクリプションでの利用とは経路が異なります。今回はAPI料金を試算していないため、費用が同じ、必ず安い、月額だけで無制限といった判断はしません。

## 会社のデータは、権限だけでなく契約・学習設定も確認する

2026年10月10日確認の[個人向けPrivacy Center](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)は、Pro・MaxなどのアカウントでClaude Codeを使う場合も対象としています。モデル改善への利用を許可した場合や、安全審査、明示的な参加などの条件で会話・コーディングデータが使われると説明しています。

同日の[商用製品向け説明](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)では、商用製品の入力・出力を初期設定ではモデル学習に使わないとする一方、フィードバックや明示的な許可などの例外を説明しています。

有料だからすべて同じ扱い、Localだから外に出ない、学習に使われないから保存もされない、といった判断は避けます。社内ルール、契約、保管、外部接続、フィードバック送信を分けて確認してください。運用ルールの整理は[生成AIの社内ガイドラインには何を書けばいいですか](/posts/seisei-ai-guideline-shanai-tsukurikata)を参照できます。

## 使えるかどうかより、確認して直し続けられるか

社内ツールを試すなら、対象業務1つ、練習用コピー、変更1つという小さな単位から始めます。AIが変更を出せても、担当者が内容を理解できず、戻せず、保守もできない状態なら、業務への反映は保留します。

外部に相談する場合は、成果物、テストの範囲、設定やコードの受け渡し、保守担当を先に確認してください。作る方法の全体像は[AIエージェントの作り方は？中小企業が自社で作るときの3つの方法と手順](/posts/ai-agent-tsukurikata)で整理しています。Claude Codeは開発支援のツールであり、作ったものの業務適合性を代わりに判断する責任者ではありません。
