# Copilot Studioとは何ですか。Microsoft 365 Copilotとの違いと中小企業での判断基準

答え: Copilot Studioは、AIエージェントとワークフローをローコードで作り、公開して運用するためのMicrosoftのツールです。Microsoft 365 Copilotが既製のアシスタントを使う側、Copilot Studioは自社用のエージェントを作る側、という位置づけの違いがあります。

対象読者: Microsoft 365を契約していて、社内問い合わせ対応や定型処理を自社用のAIエージェントに任せられるか検討している中小企業の経営者や、情報システムを兼任している総務・事務の責任者
対象キーワード: copilot studio とは（日本・月間1600件／KD0）
公開: 2026-09-26 ／ 更新: 2026-09-28
出典URL: https://ai-i2gajxb-preview-4200.runable.site/posts/copilot-studio-towa

Microsoft 365の案内やセミナーの告知で「Copilot Studio」という名前を見かけて、Microsoft 365 Copilotと何が違うのか分からないまま保留にしている、という状態はよくあります。名前が似ていて、しかも同じ価格ページの中に並んで出てくるため、契約の関係が見えにくいのが原因です。

結論から書きます。Copilot Studioは、AIエージェントとワークフローをローコードで作り、社内や自社サイトに公開して運用するためのツールです。Microsoft 365 Copilotが既製のアシスタントを使う側であるのに対し、Copilot Studioは自社用のエージェントを作る側にあたります。そして費用の考え方も違い、ユーザー単位の月額ではなく、エージェントが動いた量をCopilotクレジットという単位で測って課金されます。

## Copilot Studioで作れるものは3種類

Microsoft Learnの概要ページ（2026年9月26日に確認）では、Copilot Studioは「AI搭載のエージェントやワークフローの構築と管理のためのグラフィカルでローコードなスタジオ」と説明され、構築できるものが3つの構成要素に分けて紹介されています。単独で使うことも、組み合わせて業務プロセスを自動化することもできるとされています。

| 構成要素 | 公式ページでの説明 | 中小企業での使いどころ |
| --- | --- | --- |
| エージェント | 会話を処理しタスクを完了するAIアシスタント。指示に従い、接続した知識源を活用し、次の最善のステップを判断して行動する | 社内規程や手順書に基づく問い合わせ対応。Teamsや自社サイトに出す窓口 |
| ワークフロー | ドラッグ&ドロップのデザイナーで作る自動化。各ステップが推論と行動を行え、組み込みテストと人間によるコントロールを含む | 申請の受付から担当者への割り振りまで、決まった順番のある処理 |
| エージェントフロー | Power Automateに似たオーサリング体験を持ち、Copilot Studioにネイティブで提供される。独立した実行も、エージェントに割り当てるツールとしての利用も可能 | 既存のPower Automateの作り方に近い形で、エージェントから呼ぶ処理を用意する |

エージェントの公開先として、Microsoft Teams、Microsoft 365 Copilot、ウェブサイト、モバイルアプリ、その他のチャネルが挙げられており、複数言語で従業員や顧客と連携できるとされています。

もう1つ押さえておきたいのが「ハーネス」です。同ページでは、作ったものはすべてハーネスの上で動き、ハーネスの選択が推論の仕方、対応できるタスクの複雑さ、標準で実行できること、そして課金方法に影響すると説明されています。提供されているのは、推論重視で多段階の作業や複雑なビジネスプロセスに対応するGitHub Copilotハーネス、ルールベースのエージェントと構造化され再現可能な会話のための標準ハーネス、組織の知識を活用してMicrosoft 365 Copilot Chatを拡張するCopilotチャットハーネスの3種類です。後述するライセンスや課金の資料は「標準ハーネスで駆動されるエージェント」を対象にしたものが多いため、資料を読むときはどのハーネスの話かを確認する必要があります。

なお、このページの冒頭には、トピックの一部が機械翻訳またはAI翻訳されている場合があるという注意書きがあります。日本語の表現が不自然な箇所は、英語版と突き合わせたほうが確実です。

## Microsoft 365 CopilotとCopilot Studioの違い

日本向けの価格ページ（2026年9月26日に確認）の表示を並べると、関係がはっきりします。

| 項目 | Microsoft 365 Copilot | Copilot Studio |
| --- | --- | --- |
| 立ち位置 | 既製のアシスタントを使う | 自社用のエージェントやワークフローを作る |
| 表示価格 | 年払いでユーザーあたり月額4,497円相当（税別） | 購入前プラン（プリペイドのCopilotクレジットコミットユニット）または従量課金制 |
| 課金の単位 | ユーザー単位 | エージェントの使用量（Copilotクレジット） |
| 含まれるもの | Copilot ChatとCopilot Studioの標準ハーネスへのアクセス | 自律型エージェントの構築、ウェブサイトやアプリなど外部チャネル向けのエージェント作成 |
| 前提 | 条件を満たすMicrosoft 365の大企業または一般法人向けプラン | エージェントを使用するにはAzureサブスクリプションが必要 |

ここで重要なのは、Microsoft 365 Copilotのプラン説明に「Copilot ChatとCopilot StudioのStandardハーネスへのアクセスが含まれます」と書かれている点です。すでにMicrosoft 365 Copilotを契約している会社は、標準ハーネス上でエージェントを作る入口を持っていることになります。一方、自社サイトや外部のチャネルに出す自律型のエージェントは、Copilot Studio側のプランとAzureサブスクリプションが前提になります。

Microsoft 365 Copilot側でできることの範囲は[Microsoft 365 Copilotでは何ができますか。中小企業が導入を判断する基準は](/posts/microsoft-365-copilot-nani-ga-dekiru)で整理しています。

## 「無料」の意味を取り違えない

Microsoft Learnのライセンスのページ（2026年9月26日に確認）には、Copilot Studioを使うために必要な構成が列挙されています。入口ごとに条件が違うため、表にまとめます。

| 入口 | 公式ページでの記載 | 公開できるか |
| --- | --- | --- |
| Copilot Studio ユーザー ライセンス（無料） | 管理者がMicrosoft管理センターで作成者に割り当てる。取得にはCopilot Studio テナント Copilot クレジット パック予約購入サブスクリプションが必要 | 環境へのメッセージ割り当て、またはテナントプールからの引き当てが有効なら可 |
| Microsoft 365 Copilot ライセンス | Copilot Studioを使ってエージェントでMicrosoft 365 Copilotを拡張できる | 可 |
| Copilot Studio 試用版ライセンス | 個人としてサインアップでき、エージェントの作成とテストチャットパネルでのテストができる | 不可（公開を許可する資格がないと明記） |
| 従量課金制（Azureサブスクリプション） | ライセンスコミットメントや事前購入なしで開始でき、月末に実際に使ったクレジット分だけ支払う | 可 |

「ユーザーライセンスは無料」という記述だけを見ると費用がかからないように読めますが、その取得条件としてテナント側の有償のクレジットパック購入が挙げられています。作成者に配るライセンス代がかからない、という意味です。

試して終わりにせず社内で実際に運用するつもりなら、試用版では公開できないという制約も最初に押さえておきます。課金とライセンスのFAQには、公開が許可される条件が4通り示され、試用版ライセンスは公開の対象外と明記されています（2026年9月26日に確認）。

## 費用はCopilotクレジットの消費量で決まる

Microsoft Learnの請求レートのページ（2026年9月26日に確認）では、Copilotクレジットが「エージェントの使用状況を測定する単位」とされ、機能ごとの消費量が表で示されています。主なものを抜き出します。

| エージェントの機能 | 請求レート |
| --- | --- |
| 従来型の回答（作成者が用意した固定の返答） | 1 Copilot クレジット |
| 生成回答（AIモデルが動的に生成） | 2 Copilot クレジット |
| エージェントアクション（トリガー、詳細な推論、トピック遷移など） | 5 Copilot クレジット |
| メッセージのテナントグラフの基盤設定 | 10 Copilot クレジット |
| エージェント フロー アクション（100アクションあたり） | 13 Copilot クレジット |
| テキストおよび生成AIツール（Basic、10応答ごと） | 1 Copilot クレジット |
| テキストおよび生成AIツール（標準、10回答ごと） | 15 Copilot クレジット |
| テキストおよび生成AIツール（Premium、10応答ごと） | 100 Copilot クレジット |
| ページごとのコンテンツ処理ツール | 8 Copilot クレジット |
| クラシック音声（1分あたり） | 10 Copilot クレジット |
| GenAI音声（1分あたり） | 35 Copilot クレジット |
| プレミアムGenAI音声（1分あたり） | 75 Copilot クレジット |

設計次第で消費量が大きく変わることが、この表から読み取れます。たとえば同ページには、テナントグラフに基づくエージェントが1つの複雑なプロンプトに12クレジット（基盤設定10＋生成回答2）を使う例が示されています。また、自社サイトのカスタマーサポートで1日900人が使い、平均して従来型回答4件と生成回答2件になる場合の計算例として、［(4×1)+(2×2)］×900＝7,200クレジット／日という数字が挙げられています。同じ「問い合わせ対応」でも、固定の返答で済ませるか生成回答にするか、テナントグラフに基づけるかで、消費の桁が変わります。

Microsoft 365 Copilotのライセンスを持つ利用者が社内向けに使う場合、これらのコア機能は表の右欄で「無料」とされています。ただし、フェアユースの制限に制限され、Microsoftは製品の進化や新たな使用パターンに伴い制限を更新する権利を留保するという注記が付いています。社内利用だから費用が発生しないと固定で見込むのではなく、ここは前提が変わりうる部分として扱っておくほうが安全です。

運用側の注意点も2つあります。1つ目は繰り越しです。課金とライセンスのFAQには、未使用の容量は翌月に繰り越されず、クレジット使用量は毎月1日から始まる月単位でカウントされると記載されています。2つ目は、利用者が応答しなかった場合の扱いです。エージェントがプロンプトなしでメッセージを開始するプロアクティブな応答メッセージは、エンドユーザーが応答しない場合でも課金クレジットとしてカウントされるとされています。あいさつメッセージを自動で出す設計にすると、会話が成立しなかった分も消費に乗ります。

なお、同ライセンスページには、2025年9月1日からエージェントの共通通貨がmessagesからCopilotクレジットに変更されたという記載があります。それより前に書かれた解説記事は単位の名前が違うため、金額を比べるときは注意が必要です。

## クォータと制限を先に見る

Microsoft Learnのクォータと制限のページ（2026年9月26日に確認）に、運用前に確認したい数字がまとまっています。クォータは、エージェントがメッセージを受信できる頻度の既定の制約です。

| 環境・契約の区分 | 1分あたりの要求数（RPM）／1時間あたりの要求数（RPH） |
| --- | --- |
| プリペイド メッセージ パック 1〜10 | 50 RPM／1,000 RPH |
| プリペイド メッセージ パック 11〜50 | 80 RPM／1,600 RPH |
| プリペイド メッセージ パック 51〜150 | 100 RPM／2,000 RPH |
| 150を超える分 | 10単位ごとに +1 RPM／+20 RPH |
| 試用環境または開発環境 | 10 RPM／200 RPH |
| 従量課金制環境 | 100 RPM／2,000 RPH |
| Microsoft 365 Copilot ユーザー | 100 RPM／2,000 RPH |

クォータに達すると、利用者がメッセージを送ろうとしたときにエラー通知が表示されるとされています。社内向けであれば分あたり数十件の制約が問題になる場面は限られますが、案内メールを一斉に出した直後や、繁忙期の申請受付のような集中する場面では確認が必要です。

作成側の制限も決まっています。エージェントごとの知識ソースはすべての型で500、エージェントの手順は8,000文字、ファイルアップロードのサイズは512MB、アップロードできるファイル数は500、トピックはDataverse環境のエージェントごとに1,000、トリガーフレーズはトピックごとに200、コネクタのペイロードデータは5MB（GCCプランは450KB）です。

SharePointを知識源にする場合の条件は、特に先に見ておく価値があります。同ページでは、生成オーケストレーションを使うエージェントは最大25個のSharePointサイトURLを持てるとされ、最新のSharePointページのみがサポートされ、SPFxコンポーネントを含むモダンページはサポートされないと明記されています。また、同一テナント内でMicrosoft 365 Copilotライセンスとセマンティックサーチ付きのテナントグラフグラウンディングを有効にすると、最大200MBまでのファイルがサポートされるとされています。社内資料の置き方によって、そのまま知識源にできるかどうかが変わります。

社内資料を検索できるようにする手段の選び分けは[社内にある資料をAIで探せるようにするには、どの方法が合っていますか](/posts/shanai-shiryo-ai-kensaku)で扱っています。

## 中小企業が判断する順番

Copilot Studioを検討するとき、先に決めるべきことは機能の比較ではありません。順番は3つです。

1つ目は、任せたい業務に決まった答えがあるかどうかです。就業規則、経費精算のルール、機器の使い方といった「文書に書いてある答えを返す」業務は、知識源を接続する形で素直に載ります。反対に、案件ごとに判断が変わる業務や、判断の根拠が個人の頭の中にしかない業務は、エージェントを作る前に基準を文書にする作業が必要です。

2つ目は、根拠にする資料の状態です。知識源はSharePointやファイルに置いた文書が対象になるため、どこに最新版があるのか分からない資料は、そのまま接続すると古い内容を返します。バージョンの整理と、閲覧権限の棚卸しが先に来ます。

3つ目は、作った後に直す人がいるかどうかです。概要ページには、運用面としてアナリティクス（パフォーマンスの監視、カスタム指標の追跡、セッション成果の分析）、評価（公開前後にテストセットと共有グレーダーライブラリで品質を検証）、管理（エージェントの在庫管理、セキュリティ管理、役割ベースのアクセスとコスト管理）が挙げられています。作る工程よりも、公開後に回答のずれを直し続ける工程のほうが長く続きます。ローコードであることは、この工程を省いてよいという意味ではありません。

| 検討している業務 | Copilot Studioが素直に載るか | 補足 |
| --- | --- | --- |
| 就業規則や経費規程の問い合わせ対応 | 載りやすい | 文書があり、答えが一意に決まる。知識源の更新担当を決めることが条件 |
| 手順書に基づく機器やシステムの操作案内 | 載りやすい | 手順書の最新版の場所が確定していることが前提 |
| 申請の受付と担当者への割り振り | 条件付き | ワークフローやエージェントフローの設計が必要。承認の線引きを先に決める |
| 自社サイトでの顧客向け問い合わせ対応 | 条件付き | 外部チャネル向けはCopilot Studio側のプランとAzureサブスクリプションが前提。消費量の見積もりが必要 |
| 案件ごとに判断が変わる見積や与信の判断 | 載りにくい | 判断基準が文書化されていない業務は、基準づくりが先 |
| 紙の書類の読み取り | 別の手段が必要 | 進め方は[中小企業がAI-OCRで紙の書類をデータ化するには、何から始めればいいですか？](/posts/ai-ocr-chusho-kigyo-hajimekata)で扱っています |
| 既存システムへの入力作業の代行 | 別の検討が必要 | 手段の選び分けは[RPAとAIの違いは何ですか。どちらを選ぶべきですか](/posts/rpa-ai-chigai-dochira)を参照 |

## 社内で使うなら決めておくこと

エージェントを公開すると、社員から見れば「会社が用意した回答窓口」になります。回答が間違っていたときに誰が直すのか、どの資料を根拠にしてよいのか、個人情報や取引先の情報を入力してよいのかを、公開前に文書にしておく必要があります。入力ルールの決め方は[生成AIの社内ガイドラインには何を書けばいいですか](/posts/seisei-ai-guideline-shanai-tsukurikata)にまとめています。

また、権限の扱いはMicrosoft 365側の設定がそのまま影響します。閲覧権限が広く付いたままの人事や原価の資料が知識源に含まれていれば、エージェント経由で内容が出てきます。知識源に何を入れるかを決める作業は、資料の権限を見直す作業と同じものだと考えてください。

## よくある質問

### Copilot Studioとは何ですか
AIエージェントとワークフローを作って管理するための、ローコードのツールです。Microsoft Learnの概要ページ（2026年9月26日に確認）では、Copilot Studioは「AI搭載のエージェントやワークフローの構築と管理のためのグラフィカルでローコードなスタジオ」と説明され、エージェントやワークフローを構築し、組織のデータやシステムに接続し、利用者がすでに活動しているチャネルに公開するものとされています。作れるものは3種類に整理されています。1つ目はエージェントで、会話を処理してタスクを完了するAIアシスタントです。与えた指示に従い、接続した知識源を活用し、Microsoft Teams、Microsoft 365 Copilot、ウェブサイト、モバイルアプリなどのチャネルを通じて従業員や顧客と複数言語でやり取りできるとされています。2つ目はワークフローで、ドラッグ&ドロップのデザイナーで作る自動化です。各ステップが推論と行動を行え、組み込みのテストと人間によるコントロールが含まれるとされています。3つ目はエージェントフローで、Power Automateに似たオーサリング体験を持ちながらCopilot Studioにネイティブで提供され、独立した自動化として実行するか、エージェントに割り当てて結果を返すツールとして使えるとされています。アクセス先は https://copilotstudio.microsoft.com のスタンドアロンWebアプリです。ローコードとはいえ、知識源の整理・権限の設計・公開後の検証は自社で決める作業として残ります。

### Copilot StudioとMicrosoft 365 Copilotの違いは何ですか
使う側と作る側の違いです。Microsoft 365 Copilotは、WordやExcel、Outlook、Teamsの中で動く既製のアシスタントで、利用者は出来上がった機能を使います。Copilot Studioは、自社の業務に合わせたエージェントやワークフローを自分で設計して公開する側のツールです。日本向けの価格ページ（2026年9月26日に確認）では、Microsoft 365 Copilotのプラン説明に「Copilot ChatとCopilot StudioのStandardハーネスへのアクセスが含まれます」と書かれており、Microsoft 365 Copilotのライセンスを持っていれば、標準ハーネス上でのエージェント構築の入口はすでに手元にあることになります。一方で、同ページのCopilot Studio側のプラン（購入前プランと従量課金制）には「自律型エージェントを構築し、ウェブサイトやアプリ、ソーシャル プラットフォームなど外部チャネル向けのエージェントを作成」という説明が付き、注記として「エージェントを使用するにはAzureサブスクリプションが必要です」と記載されています。つまり、社内のMicrosoft 365の中だけで使うエージェントか、自社サイトなど外部のチャネルに出すエージェントかで、必要な契約が変わります。Microsoft 365 Copilot側でできることの範囲は[Microsoft 365 Copilotでは何ができますか。中小企業が導入を判断する基準は](/posts/microsoft-365-copilot-nani-ga-dekiru)にまとめています。

### Copilot Studioは無料で使えますか
ライセンス自体は無料のものがありますが、条件が付きます。Microsoft Learnのライセンスのページ（2026年9月26日に確認）には、Copilot Studioを使うために必要な構成の1つとして「Copilot Studio ユーザー ライセンス（無料）」が挙げられており、管理者がMicrosoft管理センターで作成者に割り当てるとされています。ただし同じ箇所に、このユーザーライセンスを取得するには「Copilot Studio テナント Copilot クレジット パック予約購入サブスクリプション」が必要だという注記が付いています。作成者に配るライセンスに費用がかからないという意味で、テナント側に有償のクレジットパックが要る、という構成です。このほかに、Microsoft 365 Copilotライセンスを持っている場合と、Copilot Studio試用版ライセンスの場合も利用可とされています。試用版については、Copilot Studioにアクセスしてエージェントを作成でき、テストチャットパネルでテストもできるものの、エージェントを公開することはできないと明記されています。課金とライセンスのFAQ（2026年9月26日に確認）でも、公開が許可される条件としてMicrosoft 365 Copilotライセンスの割り当て、Copilot Studioユーザーライセンスとメッセージの割り当て、テナントプールからの引き当ての有効化、Officeライセンスのみで生成AI機能を使わない場合のいずれかが挙げられ、「試用版ライセンスは、公開を許可する資格がありません」と書かれています。試して終わりではなく社内で実際に使うつもりなら、有償の枠を前提に見積もる必要があります。

### Copilot Studioの利用料金はいくらですか
定額の月額ではなく、Copilotクレジットという単位の消費量で決まります。Microsoft Learnの請求レートのページ（2026年9月26日に確認）では、Copilotクレジットは「エージェントの使用状況を測定する単位」で、合計コストは組織が使う合計クレジット数に基づいて計算するとされています。機能ごとの請求レートは、従来型の回答が1クレジット、生成回答が2クレジット、エージェントアクションが5クレジット、メッセージのテナントグラフの基盤設定が10クレジット、エージェントフローアクションが100アクションあたり13クレジットです。AIツールは10応答ごとに、基本が1クレジット、標準が15クレジット、プレミアムが100クレジット、ページごとのコンテンツ処理ツールが8クレジットとされています。音声は1分あたりで、クラシック音声が10クレジット、GenAI音声が35クレジット、プレミアムGenAI音声が75クレジットです。同ページには、テナントグラフに基づくエージェントが1つの複雑なプロンプトに12クレジット（基盤設定10＋生成回答2）を使う例が示されています。なお、Microsoft 365 Copilotライセンスを持つ利用者が社内向けに使う場合、これらのコア機能は無料と表の右欄に記載されていますが、フェアユースの制限があり、Microsoftが制限を更新する権利を留保するという注記も付いています。取得方法は、従量制メーター、事前購入プラン、Copilotクレジット前払いパックの3通りで、価格ページには「Copilot クレジット コミット ユニットを前払いで購入すると、コストを最大20%削減できます」と記載されています。金額そのものは契約形態と消費量で変わるため、Microsoftのエージェント使用量見積もりツールで自社の想定トラフィックを入れて確認するのが確実です。

### Copilot Studioの利用量に上限はありますか
クォータと制限の両方があります。Microsoft Learnのクォータと制限のページ（2026年9月26日に確認）では、クォータは「エージェントがメッセージを受信できる頻度を制限する既定の制約」で、使用量の急増から保護するためのものと説明されています。Dataverse環境ごとの1分あたりの要求数（RPM）と1時間あたりの要求数（RPH）は、プリペイドメッセージパック1〜10で50RPM／1,000RPH、11〜50で80RPM／1,600RPH、51〜150で100RPM／2,000RPH、150を超える分は10単位ごとに+1RPM／+20RPHとされています。試用環境または開発環境は10RPM／200RPH、従量課金制環境とMicrosoft 365 Copilotユーザーは100RPM／2,000RPHです。クォータに達すると、利用者がメッセージを送ろうとしたときにエラー通知が表示されるとされています。作成側の制限も決まっています。エージェントごとの知識ソースはすべての型で500、エージェントの手順は8,000文字、コネクタのペイロードデータは5MB、ファイルアップロードのサイズは512MB、アップロードできるファイル数は500、スキルはエージェントごとに100、トピックはDataverse環境のエージェントごとに1,000、トリガーフレーズはトピックごとに200です。SharePointを知識ソースにする場合、生成オーケストレーションを使うエージェントは最大25個のSharePointサイトURLを持てるとされ、最新のSharePointページのみがサポートされ、SPFxコンポーネントを含むモダンページはサポートされないと明記されています。社内資料をそのまま知識源にする前に、この対象外の条件を確認しておく必要があります。

### 社内問い合わせ対応なら、Copilot Studioと専用のチャットボットサービスのどちらを選ぶべきですか
判断の軸は3つです。1つ目は、社内の情報がどこにあるかです。SharePointやOneDrive、Teamsに集まっているなら、権限や知識源の接続がそろっているCopilot Studio側が素直です。ファイルサーバーや紙、個人のPCに散っている場合は、どちらを選んでも先に置き場所を決める作業が必要になります。2つ目は、費用の形です。Copilot Studioは消費量に応じたクレジット課金で、課金とライセンスのFAQ（2026年9月26日に確認）には、未使用の容量は翌月に繰り越されず、クレジット使用量は毎月1日から始まる月単位でカウントされると記載されています。問い合わせ件数の変動が大きい業務では、月額固定のサービスと比べて見積もりの前提が変わります。3つ目は、社内に作る人と直す人がいるかどうかです。ローコードでも、トピックの設計、知識源の更新、公開後の検証は誰かが継続して持つ必要があります。選択肢ごとの費用感の比較は[社内チャットボットの費用はいくらかかりますか。専用サービスと汎用AIの使い分けは](/posts/shanai-chatbot-hiyo-hikaku)、問い合わせ対応そのものの進め方は[社内の問い合わせ対応をAIに任せるには、何から始めればいいですか](/posts/ai-toiawase-taio-hajimekata)で扱っています。
